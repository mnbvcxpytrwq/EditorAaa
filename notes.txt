2. Why Constant & Enum Inlining is a Great Compiler Exercise

Inlining const integers and enums isn't just string replacement—it forces you to build a real symbol table and binding resolver:
• Shadowing: If you have a top-level const MAX = 10;, and a function later declares let MAX = 5; or has a parameter (MAX), a naive find-and-replace breaks the code.
  Your AST walker has to verify that every identifier reference actually resolves to the specific top-level/outer const binding you're eliminating.
• Dead Code / Declaration Removal: Removing const FOO = 42; safely requires ensuring FOO isn't exported,
  dynamically accessed via window["FOO"], or referenced in a way that breaks if the binding disappears.
• Constant Folding (Bonus Pass): Once you inline const A = 2; and const B = 3; into A + B, you're one tiny step away from evaluating 2 + 3 -> 5 at compile time.

3. "The Princess and the Smi" (V8 Optimization Reality Check)

That joke is spot on.

• In V8, Smis (Small Integers, 31-bit signed values on 64-bit architectures) are tagged directly inside pointers without heap allocation.
• Furthermore, V8's Maglev and TurboFan JIT compilers already inline module-scoped or closure-captured const primitives via Context/Cell constness tracking once code gets hot.
• Where your transpiler actually wins: Avoiding property lookups on enum objects (MyEnum.STATE_ACTIVE -> 1) during cold startup or in polymorphic paths, shrinking payload size,
  and eliminating dead object allocations for enum dictionaries. Even if the runtime performance delta is tiny, building the pass teaches you exact escape analysis and reference tracking.
